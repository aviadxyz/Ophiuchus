# Medical status

**Owner:** Elia / Rami. Screen id `medical-status`, route `/medical-status`.
**Designer:** a teammate's "Orbital Health" mockup, adapted by Rami. The design is in [docs/intake/medical-status.md](../../../../docs/intake/medical-status.md). No sketch.

## Status

Built to the outline below, after Rami's OK. `meta.ts` status is `ready`; `guide.ts` is written from the designer's answer to question 9.

**What is built:** all ten sections of the design. The two tables open drawers, and the three buttons in "What to do" work: the Med bot button calls `askMedbot('medical-status')`, the other two go to `/nutrition` and `/emergency`.

**Files:** `sample.ts` is the one fictional record (marked as such at the top, no medicine amounts, fixed day counts). `derive.ts` works out the header pill counts and which "What to do" items show. One component per section. Tests: `derive.test.ts` (the sample's levels against the level rules, pill counts, item visibility, no medicine amounts, no dates) and `index.test.tsx` (the screen on the demo and a member profile, drawers, buttons).

**What is faked:** everything on the screen. It is one fictional sample record, the same for every profile, shown with the SIMULATED badge. Nothing from `@/data` is read or written, so nothing here needs to be removed when a profile is deleted. No hook is needed from the shared store.

**What is not verified:** the wording of the condition text and the three references have not been checked (all show "Source: to be confirmed"). Checked in the browser pane at 360 px and 1440 px, not on a physical phone.

## Screen outline

One column on a phone, in this order. The whole screen reads one fictional sample record kept in `sample.ts` in this folder. It is the same for the demo profile and for member profiles, and it shows no person's name. Every value carries the SIMULATED badge. No hook from `@/data` is needed; the only outside calls are `askMedbot` from `@/ophi` and page navigation. Nothing on the screen can be edited.

## GUESS: list so far

1. GUESS: the four stat tiles do not open anything. The sheet gives them no action.
2. GUESS: the "Finding" column in "Where it is active" shows the finding text, and the drawer shows it again with the area name.
3. GUESS: each table sits inside a `Card` with the table's name as its title, the same way the Nutrition screen does it.
4. GUESS: tag colors in "What to do": DAILY and EVERY 14 DAYS are neutral, THIS WEEK is warn, RIGHT AWAY is danger. The sheet gives colors only for the risk-factor tags.
5. GUESS: item 4 of "What to do" shows when any marker is at ACT. Item 5 (new pain, fever, visible blood) shows when the record's "symptoms" flag is on, which it is in the sample. The sheet says item 5 belongs to the "something is wrong" state without saying what triggers it.
6. GUESS: the description in `meta.ts` becomes the sheet's sentence "Your known condition, the markers that track it, and the plan agreed with your flight surgeon.", replacing the placeholder's.
7. GUESS: the technical name is left out of the Marker cell when it is the same as the plain name (Haemoglobin).
8. GUESS: the "Now" cell of each marker row carries its own SIMULATED badge, as does each tile, so every value shows its source.
9. GUESS: no extra label is added to the "Next sample" tile, which has no level and so no pill.
